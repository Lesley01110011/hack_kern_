# PARADON: подключения и зоны ответственности

Приложение — Next.js. Браузер не ходит на портал и к модели сам: он говорит только с маршрутом `/api`. Портал «Работа в России» и модель вызывает тот же процесс Node, в котором открыт сайт. Новое окно при этом не появляется.

```text
Браузер (app/page.tsx + components/dashboard.tsx)
        |  HTTP JSON, только /api?action=
        v
app/api/route.ts  ->  lib/api.ts
        |  кнопка «Обновить» в том же процессе
        v
lib/runner.ts
        |                         |
        | FetchHttpClient         | LlmClient, если модель настроена
        v                         v
opendata.trudvsem.ru      GigaChat, https://api.giga.chat/v1
регион 39                 модель GigaChat-2

Результат пишется в data/report.json, data/vacancies.json, data/status.json.
Браузер читает эти файлы снова через /api.
```

## 1. Браузер и локальный API

Экран открывается в окне Node.js (приглашение `>`) двумя строками: `process.chdir('C:/OSPanel/home/Hack')`, затем `require('./server.js')`. Браузер открывается сам на `http://localhost:3000/`. Компонент `components/dashboard.tsx` не знает адрес портала и ключ модели. Все запросы идут на `/api`.

| Действие в интерфейсе | Запрос | Кто отвечает |
| --- | --- | --- |
| Открытие списка и отчёта | `GET /api?action=report` и `GET /api?action=status` | `ReportStore` читает `data/report.json`, `RunStatus` читает `data/status.json` |
| Пока идёт проверка | те же два запроса каждые 1,5 с | статус `running`, счётчик `processed/total` |
| Карточка вакансии | `GET /api?action=vacancy&id=` | `storedVacancy()` берёт поля из `data/vacancies.json` |
| Кнопка «Обновить» и «Запустить проверку» | `POST /api?action=run` | `Runner.execute` идёт в том же процессе, без нового окна |
| «Загрузить JSON» | `POST /api?action=fixture` | файл до 5 МБ кладётся в `data/inbox.json`, затем `Runner` разбирает вакансии из этого файла |
| Экран «Настройки», открытие | `GET /api?action=config` | `Config` отдаёт `data/config.json`, ключ маскируется как `********` |
| «Сохранить» | `POST /api?action=config` | `Config.save` перезаписывает `data/config.json`. Пустой ключ или `********` старый ключ не затирает |
| «Учебное резюме» | `GET /api?action=sample-resume` | текст `fixtures/sample_resume.txt` |
| «Сформировать черновик» | `POST /api?action=resume` | `LlmClient.draftResume`, текст возвращается на экран «Резюме» |

Если проверка уже идёт, маршрут отвечает `409` и текстом «Проверка уже выполняется». Замок — файл `data/run.lock` с pid процесса. После завершения замок удаляется.

## 2. Откуда берётся вакансия

Рабочий источник задаётся полем `source_url`. По умолчанию:

`http://opendata.trudvsem.ru/api/v1/vacancies/region/39`

Это открытые данные портала «Работа в России», регион 39, Калининградская область. Документация портала: `https://trudvsem.ru/opendata/api`.

Кто ходит наружу: `VacancySource` через `FetchHttpClient`.

Запрос:

```text
GET {source_url}?offset={пропуск записей}&limit={размер страницы}
Accept: application/json
```

`offset` — это сдвиг по записям, не номер страницы. Ответ ожидается как конверт портала: `results.vacancies[].vacancy` и `meta.total`. `unwrap` в `lib/normalizer.ts` достаёт из него массив вакансий.

Правила объёма:

- за один запуск берётся не больше `max_vacancies`;
- если лимит не меньше 2 и размер страницы не меньше лимита, размер страницы уменьшается до половины лимита, чтобы получилось минимум два запроса;
- цикл останавливается, когда набрано нужное число, каталог кончился или прочитано 50 страниц;
- одинаковый `id` внутри запуска остаётся один раз.

Проверочный режим портал не вызывает. `npx tsx scripts/run.ts --fixture путь` читает локальный JSON того же формата и разбирает все вакансии из файла, лимит `max_vacancies` на него не действует.

Если портал не ответил, вернул не JSON или HTTP-ошибку, `ReportStore.fail` записывает текст ошибки и время, а массив `items` прошлого успешного отчёта не стирает. В шапке интерфейса индикатор становится «API недоступен».

## 3. Модель

Модель необязательна для отчёта. Без неё замечания собирает `RuleAnalyzer`. С ней замечания переписывает и дополняет модель, а жёсткие пропуски и противоречия правил возвращаются, если модель их выкинула.

Подключение читается из `data/config.json`:

| Поле | Смысл |
| --- | --- |
| `llm_base_url` | Адрес GigaChat, без `/chat/completions`: `https://api.giga.chat/v1` |
| `llm_model` | `GigaChat-2` |
| `llm_api_key` | Ключ авторизации из кабинета GigaChat. В репозиторий не кладётся |
| `llm_timeout_sec` | Сколько секунд ждать ответ, не меньше 10 |

Модель считается подключённой, когда заданы имя `GigaChat-2` и ключ авторизации.

Клиент сначала обменивает ключ на токен доступа по адресу `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` (область `GIGACHAT_API_PERS`), затем вызывает `POST https://api.giga.chat/v1/chat/completions`. Ключ и токен в журнал не пишутся. Поле `response_format` для GigaChat не отправляется.

```text
Authorization: Bearer {токен доступа}
Content-Type: application/json

{
  "model": "GigaChat-2",
  "temperature": 0.1,
  "messages": [
    {"role": "system", "content": "инструкция из Prompt"},
    {"role": "user", "content": "JSON полей вакансии"}
  ]
}
```

Для разбора вакансии в теле только рабочие поля, без контактов и ИНН. Если сервер не принимает `response_format` и отвечает HTTP 400, запрос повторяется без этого поля.

Текст инструкции лежит в `lib/prompt.ts`: `analyzerPrompt()` для замечаний, `resumePrompt()` для черновика резюме. Черновик просит обычный текст, не JSON.

Ответ модели для замечаний проходит `Analyzer`: тема только из семи допустимых, цитата должна находиться в полях вакансии, пустая цитата у пропуска не превращается в ложное «поле пустое», если факт уже есть в структурированном поле.

В отчёте:

- `ai_used: true` — модель ответила по всем вакансиям этого запуска или ответы взяты из кэша при подключённой модели;
- `ai_error` — модель не настроена, недоступна или ответила только по части вакансий. В последнем случае для остальных остаются структурные проверки.

Кэш `data/cache.json` хранит замечания по `id` и отпечатку полей плюс версии правил и адреса модели. Пока вакансия и модель не изменились, повторный запрос к модели не отправляется.

Черновик резюме вызывается сразу из `/api?action=resume`, не через фоновый `scripts/run.ts`. Если модель не настроена, кнопка «Собрать черновик» получает текст ошибки, отчёт по вакансиям при этом не ломается.

## 4. Три способа запустить одну и ту же проверку

Все три в итоге вызывают `Runner.execute`.

| Способ | Что происходит |
| --- | --- |
| Кнопка «Обновить» | `/api` запускает `Runner.execute` в том же окне Node.js. Интерфейс не ждёт окончания и опрашивает статус |
| `node --import tsx scripts/run.ts` | Тот же разбор в текущем окне Node.js. Аргументы `--max`, `--page-size`, `--fixture` |
| `node --import tsx scripts/scheduler.ts` | Бесконечный цикл. Каждые 20 секунд читает настройки. Если «Запускать по расписанию» включено и с прошлого раза прошёл `interval_minutes`, вызывает `Runner.execute` в этом же процессе |

Время прошлого планового запуска лежит в `data/schedule_state.json`. Само по себе включение флажка ничего не качает: процесс планировщика должен быть открыт.

## 5. Что делает каждый файл

| Файл | За что отвечает |
| --- | --- |
| `app/page.tsx`, `app/layout.tsx` | Страница Next.js и общий каркас |
| `components/dashboard.tsx` | Экраны: список, разбор, отчёт, настройки, черновик. Запросы к `/api`, фильтры, карточки, подсветка цитат, копирование уточнения |
| `app/globals.css` | Внешний вид, к данным и сети не подключается |
| `app/api/route.ts` | Единственная дверь браузера. Передаёт `action` в `lib/api.ts` |
| `lib/api.ts` | Разбирает действие и отдаёт JSON |
| `lib/config.ts` | Чтение и запись `data/config.json`, проверка «модель подключена» |
| `lib/http.ts` | `FetchHttpClient` — GET JSON портала |
| `lib/vacancy-source.ts` | Страницы API, лимит, сдвиг `offset` |
| `lib/normalizer.ts` | Достаёт вакансии из конверта API и оставляет поля для разбора. Контакты и реквизиты не включает |
| `lib/rule-analyzer.ts` | Замечания без модели: пропуски, двусмысленность, противоречия |
| `lib/prompt.ts` | Тексты системных инструкций для модели |
| `lib/llm.ts` | HTTP к `/chat/completions` и разбор ответа |
| `lib/analyzer.ts` | Склеивает правила и модель, выбрасывает неподтверждённые цитаты |
| `lib/cache.ts` | Не слать ту же вакансию в модель повторно |
| `lib/runner.ts` | Замок, запуск процесса, сбор отчёта, запись файлов, сохранение прошлого отчёта при сбое |
| `lib/report-store.ts` | Форма `data/report.json`: успех заменяет отчёт, ошибка сохраняет прошлые `items` |
| `lib/run-status.ts` | Короткий статус для индикатора в шапке |
| `scripts/run.ts` | Точка входа одной проверки |
| `scripts/scheduler.ts` | Точка входа расписания |
| `fixtures/sample_api_response.json` | Учебный ответ API, портал не нужен |
| `fixtures/sample_resume.txt` | Вымышленное резюме для черновика |
| `tests/run-tests.ts` | Проверка правил, страниц, дедупликации, ошибки API и влияния модели. Наружу не ходит |

## 6. Файлы в `data/`

Каталог создаётся сам. В git он не коммитится, кроме пустого `.gitkeep`.

| Файл | Кто пишет | Кто читает | Смысл |
| --- | --- | --- | --- |
| `config.json` | Настройки в интерфейсе, первый запуск копирует `config.example.json` | `Config`, планировщик, модель | Адреса, лимиты, ключ |
| `report.json` | `ReportStore` | Интерфейс через `action=report` | Отчёт. Для оценки смотреть `items` |
| `vacancies.json` | `Runner` после успешного разбора | `action=vacancy` | Полные поля по `id` для экрана разбора |
| `status.json` | `Runner` | Индикатор «API доступен» и прогресс | `ok`, `running` или `error` |
| `cache.json` | `AnalysisCache` | Следующий запуск | Замечания, чтобы не дергать модель зря |
| `run.lock` | `Runner` | `/api` перед новым запуском | Одна проверка одновременно. Файл исчезает после завершения |
| `schedule_state.json` | Планировщик | Планировщик | Момент прошлого автоматического запуска. Появляется, только если планировщик запускали |
| `inbox.json` | «Загрузить JSON» | Запуск с `--fixture` | Последний загруженный проверочный JSON |

## 7. Что лежит в отчёте

`data/report.json` — обёртка запуска плюс строгий список.

Служебные поля обёртки: `generated_at`, `status` (`ok`, `error`, `empty`), `error`, `last_error_at`, `mode` (`api` или `fixture`), `source_url`, `pages_fetched`, `source_total`, `vacancies_processed`, `ai_used`, `ai_error`.

`items` — то, что требует задание. Один объект на вакансию:

```json
{
  "vacancy_id": "id с портала",
  "vac_url": "ссылка на карточку или null",
  "remarks": [
    {
      "topic": "название_должности | обязанности | требования | оплата | график | место_работы | тип_занятости",
      "field": "имя поля API",
      "quote": "цитата или оба значения; пустая строка, если это пропуск",
      "problem": "что мешает понять условие",
      "recommendation": "что уточнить у работодателя"
    }
  ]
}
```

`cards` — короткие подписи для списка в интерфейсе: должность, организация, оплата, график, занятость, адрес, число замечаний. Это не формат задания.

Кнопка «Скачать JSON» сохраняет только массив `items`.

## 8. Поля, которые участвуют в разборе

`fields` в `lib/normalizer.ts` отдаёт их и правилам, и модели:

`job-name`, `typicalPosition`, `duty`, `requirements`, `qualification`, `requirement.education`, `requirement.qualification`, `requirement.experience`, `salary`, `salary_min`, `salary_max`, `currency`, `schedule`, `shift`, `employment`, `addresses`, `conditions`, `skills`, `benefitDetails`, `company_name`, `work_places`.

Семь тем замечания соответствуют названию, обязанностям, требованиям, оплате, графику, месту и типу занятости. Если число или адрес уже есть в структурированном поле, отсутствие этой же фразы в тексте описанием ошибкой не считается.
