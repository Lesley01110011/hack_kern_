# Прозрачная вакансия

Прототип для редактора вакансий Калининградской области. Сервис читает карточки портала «Работа в России», разбирает название, обязанности, требования, оплату, график, место работы и тип занятости и пишет замечания редактору: где условие пропущено, сформулировано двусмысленно или противоречит другому полю. Юридических выводов нет. Если структурированное поле уже содержит факт, его повторное отсутствие в тексте ошибкой не считается. Чистая вакансия остаётся с пустым списком замечаний.

Интерфейс необязателен для проверки. Оценка смотрит отчёт `items`.

## Материалы для сдачи

| Что просит жюри | Где в репозитории |
| --- | --- |
| Исходники | `lib/`, `scripts/`, `app/`, `components/`, `server.js` |
| Конфигурация запуска, расписания и GigaChat | `config.example.json`, `scripts/run.ts`, `scripts/scheduler.ts` |
| Учебные данные в формате API портала | `fixtures/sample_api_response.json` |
| Учебное резюме | `fixtures/sample_resume.txt` |
| Пример отчёта на учебных данных | `fixtures/sample_report.json` |
| README | этот файл |

SHA коммита для письма жюри — вывод `git rev-parse HEAD` у того коммита, который отправляете на оценку. Ключи в этот коммит не входят: `data/*.json` перечислен в `.gitignore`, в примерах конфигурации поле `llm_api_key` пустое.

## Настройки

Рабочий файл — `data/config.json`. Его нет в репозитории. При первом запуске он копируется из `config.example.json`. В примере уже стоят адрес и модель GigaChat, поле ключа пустое.

| Параметр | Смысл |
| --- | --- |
| `source_url` | Адрес API. По умолчанию `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` |
| `max_vacancies` | Сколько вакансий разбирать за рабочий запуск |
| `page_size` | Сколько записей просить на страницу |
| `schedule_enabled` | Включён ли планировщик |
| `interval_minutes` | Пауза между автоматическими запусками |
| `llm_base_url` | Адрес GigaChat. В примере `https://api.giga.chat/v1` |
| `llm_model` | Модель GigaChat. В примере `GigaChat-2` |
| `llm_api_key` | Ключ авторизации из личного кабинета GigaChat. В репозиторий не кладётся |
| `llm_timeout_sec` | Сколько секунд ждать ответ модели |

Если лимит не меньше 2 и в каталоге больше одной страницы, сервис запрашивает минимум две страницы: размер страницы уменьшается, когда он не меньше лимита. В проверочном режиме лимит не действует, разбирается весь файл. Повторный запуск не создаёт вторую строку на тот же `vacancy_id`. Неизменившаяся вакансия не отправляется в модель второй раз. Если портал недоступен, в отчёте остаётся последний успешный список и пишется текст ошибки.

Ключ хранится только в `data/config.json` на машине, где запускаете сервис. В интерфейсе сохранённый ключ показывается как `********` и пустая отправка его не затирает.

## С чего начинается обработка

Обработка начинается с `scripts/run.ts`. Скрипт создаёт `Runner` и вызывает `Runner.execute` в `lib/runner.ts`.

Дальше по шагам:

1. `lib/vacancy-source.ts` читает страницы API либо `lib/runner.ts` читает проверочный JSON.
2. `lib/rule-analyzer.ts` отмечает пустые поля и прямые противоречия.
3. Если модель подключена, `lib/analyzer.ts` вызывает `LlmClient.suggest` в `lib/llm.ts`. Это шаг, на котором используется ИИ: модель переписывает замечания своими словами и добавляет неоднозначности, которых нет в структурных правилах. Цитата без опоры на поля вакансии отбрасывается.
4. `lib/report-store.ts` записывает `data/report.json`.

Ручной запуск из интерфейса идёт в тот же `Runner.execute`, отдельный процесс не стартует. Расписание — отдельный процесс `scripts/scheduler.ts`: раз в 20 секунд он смотрит `schedule_enabled` и `interval_minutes` в `data/config.json` и в срок вызывает тот же `Runner.execute`.

## Команды

Проверки правил, без портала и без модели:

```text
npm test
```

Учебный отчёт из `fixtures/sample_api_response.json`. Портал не вызывается. Результат перезаписывает `data/report.json`:

```text
npm run report -- --fixture fixtures/sample_api_response.json
```

Рабочий сбор с портала, лимит и адрес берутся из `data/config.json`:

```text
npm run report
```

Планировщик, пока открыто окно процесса:

```text
npm run schedule
```

Интерфейс на `http://localhost:3000`:

```text
npm start
```

Остановка любого из процессов — `Ctrl+C`.

## Модель

Используется только GigaChat (Сбер): модель `GigaChat-2`, адрес `https://api.giga.chat/v1`. Ключ авторизации из личного кабинета записывается в `llm_api_key` файла `data/config.json` и в репозиторий не попадает. Клиент сам меняет этот ключ на токен доступа и не печатает ни ключ, ни токен.

ИИ участвует в четырёх местах, все через `lib/llm.ts`:

| Шаг | Метод | Зачем |
| --- | --- | --- |
| Сборка отчёта | `LlmClient.suggest` | замечания редактору по полям вакансии |
| Черновик письма | `draftLetter` | текст редактору по уже найденным замечаниям |
| Черновик резюме | `draftResume` | сравнение резюме с выбранной вакансией портала |
| Варианты заполнения | `fillOptions` | три варианта, если в резюме нет сведений под вакансию |

Без модели отчёт всё равно собирается структурными проверками. Тогда `ai_used` равен `false`, а в `ai_error` написано, что модель не подключена. Пример такого отчёта уже лежит в `fixtures/sample_report.json`.

## Проверочный режим с GigaChat

Платный тариф покупать не нужно. Жюри берёт бесплатный ключ авторизации для физлиц в кабинете GigaChat (область доступа `GIGACHAT_API_PERS`) и записывает его в `data/config.json`. Адрес `https://api.giga.chat/v1` и модель `GigaChat-2` уже заданы в `config.example.json`. Ключ остаётся только на машине жюри.

Учебный прогон не ходит на портал вакансий. Модель на этом шаге — тот же GigaChat:

```text
npm run report -- --fixture fixtures/sample_api_response.json
```

В `data/report.json` поле `ai_used` становится `true`, тексты `problem` и `recommendation` приходят от GigaChat. Файл `fixtures/sample_report.json` при этом не меняется: в нём заранее лежит тот же учебный набор, собранный одними правилами, пока ключ ещё не вставлен.

## Учебные данные

`fixtures/sample_api_response.json` повторяет форму ответа портала `results.vacancies[].vacancy`. Организации и люди вымышлены, портал не нужен.

| `id` | Должность | Что видно в отчёте |
| --- | --- | --- |
| `clear-metro` | Инженер по метрологии | Условия сходятся, `remarks` пуст |
| `bad-assistant` | Помощник воспитателя | Восемь замечаний: разные должности, пустые обязанности, разное образование и стаж, несходящиеся суммы, гибкий график без часов, адрес без улицы, полная и частичная занятость |
| `clear-guard` | Сторож | Смена 2/2 указана в обязанностях, `remarks` пуст |

`fixtures/sample_report.json` — отчёт по этому файлу от структурных проверок, `mode` равен `fixture`, `ai_used` равен `false`. После прогона с ключом GigaChat актуальный отчёт смотрите в `data/report.json`.

`fixtures/sample_resume.txt` — вымышленное резюме Марии Соколовой для вкладки резюме. Это не данные реального человека.

## Формат отчёта

Для оценки смотрите массив `items` в `data/report.json` или в `fixtures/sample_report.json`. Одна вакансия — один объект.

```json
{
  "vacancy_id": "string",
  "vac_url": "string или null",
  "remarks": [
    {
      "topic": "название_должности | обязанности | требования | оплата | график | место_работы | тип_занятости",
      "field": "поле API",
      "quote": "цитата или оба конфликтующих значения; пустая строка, если это пропуск",
      "problem": "что именно мешает понять условие",
      "recommendation": "что уточнить у работодателя и в какое поле записать"
    }
  ]
}
```

Пустой `remarks` значит, что по этой вакансии замечаний нет.

Служебные поля того же файла на оценку `items` не заменяют:

| Поле | Смысл |
| --- | --- |
| `generated_at` | Когда собран текущий список |
| `status` | `ok`, `error` или `empty` |
| `error` | Текст последней ошибки источника |
| `mode` | `api` или `fixture` |
| `source_url` | Адрес рабочей загрузки. В проверочном режиме `null` |
| `pages_fetched` | Сколько страниц API прочитано |
| `ai_used` | Отвечала ли модель при сборке |
| `ai_error` | Почему модель не участвовала, если `ai_used` равен `false` |
| `cards` | Краткие подписи для интерфейса |

## Вклад

Репозиторий собран как один прототип, отдельные авторы по каталогам не размечены. Автор коммита, чей SHA уходит на оценку, — участник этой поставки. По частям работы:

| Часть | Файлы |
| --- | --- |
| Загрузка портала и проверочный JSON | `lib/vacancy-source.ts`, `lib/runner.ts` |
| Структурные проверки | `lib/rule-analyzer.ts`, `lib/analyzer.ts` |
| Запросы к модели и тексты заданий | `lib/llm.ts`, `lib/prompt.ts` |
| Отчёт и кэш | `lib/report-store.ts`, `lib/cache.ts` |
| Ручной запуск | `scripts/run.ts` |
| Расписание | `scripts/scheduler.ts`, поля `schedule_enabled` и `interval_minutes` |
| Интерфейс | `server.js`, `app/`, `components/dashboard.tsx` |
| Учебные данные и пример отчёта | `fixtures/` |
